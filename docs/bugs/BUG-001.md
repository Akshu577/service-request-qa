# BUG-001: 9-digit mobile number is accepted

| | |
|---|---|
| **Severity** | Medium |
| **Requirement** | REQ-03 |
| **Found by** | TC-04b (`test_tc04b_invalid_phone_numbers_are_rejected[9-digits]`) |
| **Status** | Open |

## Steps to reproduce
```
POST /api/requests
{
  "full_name": "Sita Sharma",
  "citizenship_no": "12-01-75-01234",
  "district": "Morang",
  "phone": "984123456",
  "service_type": "Citizenship Copy"
}
```

## Expected
`422` with an error on `phone`. A Nepali mobile number has exactly 10 digits.

## Actual
`201 Created`. The request is saved with a phone number that can't be called.

## Evidence
```
FAILED tests/api/test_submit_request.py::test_tc04b_invalid_phone_numbers_are_rejected[9-digits]
AssertionError: 984123456 should be rejected
assert 201 == 422
```
11 digits, the 96 prefix, landlines and letters are all correctly rejected. Only the 9-digit case gets through.

## Likely cause
`app/app.py`: the pattern `^9[78]\d{7,8}$` allows 7 **or** 8 digits after the prefix, which means 9 or 10 digits in total. It should be `\d{8}`.

## Impact
The office can't contact the citizen about their request, and there's no error to tell anyone why.
