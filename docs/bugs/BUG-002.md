# BUG-002: Approved or Rejected request can still be changed

| | |
|---|---|
| **Severity** | High |
| **Requirement** | REQ-06 |
| **Found by** | TC-13 (`test_tc13_final_status_cannot_change`, all 8 cases) |
| **Status** | Open |

## Steps to reproduce
1. Submit a request and note the tracking ID.
2. `PATCH /api/requests/{id}/status` with `{"status": "In Review"}` (officer token).
3. `PATCH` again with `{"status": "Approved"}`.
4. `PATCH` again with `{"status": "In Review"}`.

## Expected
Step 4 returns `422`. Approved and Rejected are final.

## Actual
Step 4 returns `200` and the request goes back to `In Review`. The same happens from `Rejected`, and from either final status to any other status.

## Evidence
```
FAILED test_tc13_final_status_cannot_change[In Review-Approved]
AssertionError: Approved -> In Review should be blocked
assert 200 == 422
```
All 8 combinations (2 final statuses × 4 target statuses) fail. The normal flow (TC-10) and skipping review (TC-11) work correctly, so the rule check works for non-final statuses only.

## Likely cause
`app/app.py`, `update_status`:
```python
allowed = NEXT_STATUS[r["status"]]
if allowed and new_status not in allowed:
```
For a final status `allowed` is an empty set, which counts as false in Python, so the whole check is skipped. An empty set should mean "nothing is allowed", not "anything is allowed".

## Impact
A decision that was already given to the citizen can be silently reversed. That breaks trust in the system and in the audit history.
