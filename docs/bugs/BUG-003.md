# BUG-003: Tracking page shows the full citizenship number

| | |
|---|---|
| **Severity** | High (privacy) |
| **Requirement** | REQ-08 |
| **Found by** | TC-20 (`test_tc20_track_page_masks_citizenship_number`) |
| **Status** | Open |

## Steps to reproduce
1. Submit a request with citizenship number `27-02-70-05678`.
2. Open `/track?id=<tracking ID>` in a browser.

## Expected
Citizenship no. shows `XX-XX-XX-X5678`.

## Actual
Citizenship no. shows `27-02-70-05678` in full.

## Evidence
```
AssertionError: Locator expected to have text 'XX-XX-XX-X5678'
Actual value: 27-02-70-05678
  locator resolved to <td data-field="citizenship_no">27-02-70-05678</td>
```
The API for the same request (TC-07) masks it correctly, so the problem is only on the web page.

## Likely cause
`/track` in `app/app.py` passes the raw stored record to `track.html` instead of the masked `public_view(r)` that the API uses.

## Impact
Anyone who knows or guesses a tracking ID (they're sequential, see TC-14) can see a citizen's full citizenship number. Combined with sequential IDs, someone could go through them one by one.

## Note
Sequential tracking IDs make this worse. I'd suggest a follow-up story to make tracking IDs harder to guess.
